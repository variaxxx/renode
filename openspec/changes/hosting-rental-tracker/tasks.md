## 1. Каркас и хранение данных

- [ ] 1.1 Создать frontend на TypeScript/React с Vite, Tailwind CSS и shadcn/ui, а также backend на TypeScript/NestJS с отдельным запуском API и воркера; проверить локальный запуск и сборку frontend.
- [ ] 1.2 Настроить PostgreSQL для локальной разработки, миграции и таблицы владельца, сессий, провайдеров, серверов, платежей, уведомлений и хранилища секретов; проверить применение миграции к пустой БД PostgreSQL.
- [ ] 1.3 Добавить конфигурацию окружения и проверку обязательных параметров при старте; проверить понятную ошибку при отсутствующем параметре.

## 2. Доступ владельца

- [ ] 2.1 Реализовать одноразовую команду создания владельца с Argon2id-хешем пароля и запретом второго владельца; проверить результат в БД и отказ при повторном запуске.
- [ ] 2.2 Реализовать вход, выход, серверные сессии, безопасные cookie и ограничение попыток входа; проверить вручную успешный вход, неверный пароль и выход.
- [ ] 2.3 Закрыть API каталога, платежей, настроек и хранилища проверкой сессии и CSRF; проверить отказ без сессии и при изменяющем запросе без защиты.
- [ ] 2.4 Сделать экран входа и базовую оболочку админки из компонентов shadcn/ui с фиксированной темной темой; проверить, что все состояния экрана читаемы и закрытые страницы недоступны до входа.

## 3. Провайдеры и серверы

- [ ] 3.1 Реализовать API создания, просмотра, изменения и удаления провайдеров с запретом удаления при наличии серверов; проверить оба варианта удаления.
- [ ] 3.2 Реализовать API серверов с валидацией дат, стоимости, валюты и статуса, архивированием и правилами удаления; проверить создание, изменение и запрет удаления сервера с платежами.
- [ ] 3.3 Сделать страницы списка и карточки провайдеров и серверов с компонентами shadcn/ui, формами, поиском и фильтрами в темной теме; проверить добавление сервера и поиск по провайдеру и названию.

## 4. Хранилище паролей

- [ ] 4.1 Реализовать в браузере создание DEK, вывод ключа из мастер-пароля, AES-GCM шифрование и обертку DEK мастер-паролем и резервным ключом; проверить, что расшифровка возможна обоими способами.
- [ ] 4.2 Реализовать API хранения только шифротекста, версий формата, соли и nonce для хранилища и паролей провайдеров; проверить, что открытые пароли и ключи не появляются в запросах или БД.
- [ ] 4.3 Сделать интерфейс создания, блокировки, разблокировки и просмотра паролей с показом резервного ключа при создании; проверить, что вход в админку сам по себе не открывает пароли.
- [ ] 4.4 Реализовать восстановление по резервному ключу и смену мастер-пароля через повторное шифрование DEK; проверить доступ к ранее сохраненному паролю после смены.
- [ ] 4.5 Настроить HTTPS для развертывания, CSP и запрет сторонних скриптов на странице хранилища; проверить заголовки ответа и отсутствие сетевой передачи открытого секрета.

## 5. Платежи и обзор

- [ ] 5.1 Реализовать запись платежа и обновление даты следующей оплаты без изменения прошлых записей; проверить историю после изменения тарифа.
- [ ] 5.2 Сделать действие «Оплачено» с предлагаемой по периоду и подтверждаемой владельцем новой датой; проверить сохранение суммы, даты платежа и следующего срока.
- [ ] 5.3 Сделать обзор ближайших и просроченных платежей и ожидаемых расходов по валютам; проверить отображение серверов с разными валютами и архивного сервера.

## 6. Telegram и воркер

- [ ] 6.1 Реализовать привязку личного Telegram-чата через одноразовую ссылку, сохранение часового пояса и интервалов, а также тестовую отправку; проверить успешную привязку и сообщение об ошибке отправки.
- [ ] 6.2 Реализовать расчет напоминаний об оплате, окончании и отмене в часовом поясе владельца с отправкой в 09:00; проверить выбранные даты на примерах до и после изменения срока.
- [ ] 6.3 Реализовать воркер с транзакционной выдачей задач в PostgreSQL, уникальными записями доставки, повтором временных ошибок и пропуском архивных серверов; проверить повторный запуск без повторной отправки уже отмеченных успешными событий.
- [ ] 6.4 Проверить вручную сквозной сценарий: создать сервер, привязать Telegram, отправить тестовое и плановое напоминание, записать платеж, убедиться, что старое напоминание больше не актуально, и просмотреть все экраны в темной теме.

## 7. Развертывание и эксплуатация

- [ ] 7.1 Подготовить конфигурацию развертывания API, воркера, PostgreSQL с постоянным томом и HTTPS; проверить запуск после перезапуска процессов с сохранением данных.
- [ ] 7.2 Описать настройку владельца, Telegram-бота, резервного копирования PostgreSQL и процедуру восстановления; проверить инструкции на чистом окружении.
