# owner-access Specification

## Purpose

Обеспечивает доступ к личной веб-админке и API только одному владельцу, не открывая самостоятельную регистрацию и данные посторонним посетителям.

## Requirements

### Requirement: Single owner authentication
Система SHALL поддерживать ровно одну учетную запись владельца, вход по паролю и выход из активной сессии. Публичная регистрация SHALL отсутствовать.

#### Scenario: Owner signs in
- **WHEN** владелец вводит верный пароль
- **THEN** система создает защищенную сессию и открывает админку

#### Scenario: Invalid password
- **WHEN** посетитель вводит неверный пароль
- **THEN** система отказывает во входе без раскрытия данных каталога или хранилища секретов

### Requirement: Protected data access
Система SHALL требовать действующую сессию владельца для всех операций чтения и изменения каталога, платежей, настроек уведомлений и зашифрованных секретов.

#### Scenario: Unauthenticated API request
- **WHEN** запрос к защищенному API поступает без действующей сессии
- **THEN** система отказывает в доступе и не возвращает защищенные данные

#### Scenario: Session expires or owner signs out
- **WHEN** срок сессии истек или владелец вышел
- **THEN** последующие защищенные запросы требуют нового входа

### Requirement: Dark admin interface
Веб-админка SHALL отображать все экраны первой версии в темной теме, включая вход, каталог, платежи, настройки уведомлений и хранилище секретов.

#### Scenario: Owner opens an admin page
- **WHEN** владелец открывает любой экран админки
- **THEN** экран отображается в темной теме с читаемыми текстом, формами и состояниями элементов
